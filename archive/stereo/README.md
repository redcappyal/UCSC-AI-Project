# Archived: two-camera stereo + peer sync

**Archived 2026-07-27. Restore point: `git tag archive/stereo-v1`.**

Nothing here is deleted, imported, compiled, collected, or linted. Every file in
this directory arrived by `git mv`, so `git log --follow` reaches its full
history, and the tag above is a complete, working snapshot of the feature as
built.

---

## What it was

Two phones on opposite fin mounts record the same rally. Each detects the ball
in its own view; the two pixel tracks are triangulated into a court-frame 3D
track, and impacts are snapped to the court planes to produce a 3D line call —
IN/OUT decided from where the ball actually was in space, not from where it
appeared to be against a wall in one view.

Two delivery paths were built:

| Path | Where | What it did |
|---|---|---|
| **Offline (cloud fusion)** | `python/`, `tests/` | Both phones upload and track independently through `/api/track`, tagged with a shared `session_id` and a `camera_role` of `a`/`b`. When both runs complete, `job_runner` starts a third `stereo_fuse` job in `ui_runs/stereo-<session_id>/` that refines the clock offset between the clips and fuses them. |
| **Live (on-court)** | `ios/` | The two phones pair over BLE or Wi-Fi P2P, sync clocks by min-RTT NTP plus a clap anchor, and the secondary streams ball detections to the primary at 120 Hz. The primary runs `StereoEngine` in real time and flashes the call on screen mid-rally. |

## What state it reached

**Built and tested. Never evaluated.**

- 63 Python tests (`stereo_engine`, `stereo_sync`, `stereo_track`, `stereo_fuse`,
  the goldens, the paired-session `/api/track` contract), plus 7 more split out
  of the offline-runner tests.
- 19 iOS test files covering the peer transports, clock sync, control-message
  framing, the pairing state machine, the live session model, and the Swift/Python
  golden-parity fixture.
- The stereo math was implemented twice — Python and Swift — against one shared
  golden fixture (`tests/stereo_goldens.json`, `ios/Tests/Fixtures/stereo_goldens.json`),
  regenerated by `tests/generate_stereo_goldens.py`.
- The offset refiner beat its 2 ms live budget by roughly 3× even at an absurd
  12 px of detection noise.

### What this is NOT

*(Carried over verbatim in substance from the archived `docs/stereo-fusion.md`,
which is the fuller version and lives beside this file.)*

**The fused path is unevaluated. It must not be described as an improvement over
the monocular baseline.**

The spec was explicit that *"the fused line-call path gets an eval pass against
labeled clips before it may be called an improvement over the monocular
baseline"*, and that gate was never satisfiable from this repository:

- No paired two-camera footage exists here. The only two `.mp4`s in the tree are
  single-camera outputs.
- The one labeled clip (`bayclub_wall_hits.csv`) is single-camera, and its source
  video lives on another machine.
- Every test above runs on synthetic trajectories through synthetic cameras. That
  proves the geometry and the plumbing. It cannot prove the detector finds the
  ball in *both* views often enough on a real court — occlusion by players is the
  dominant real failure mode, and a synthetic detector is perfect by
  construction.

A paired eval clip would need: two phones on the mounts recording the same
rallies **both in the same orientation** (mixed orientations produce transposed
pixel spaces that triangulate to plausible-looking nonsense); a 4K calibration
per phone; wall-hit frames labeled on the **role a** clip so the existing
`video_sha` join works; and the `--fail-under` gate extended past IN/OUT
accuracy, which today is computed from a handful of corrections and skipped
entirely when accuracy is `None`.

Until all four exist, "unevaluated" is the honest word.

## Why it was archived

Not because it is wrong. The code is correct and tested. It is archived because
it is aimed at the wrong bottleneck.

Single-view wall-hit recall is **~35%**: of 109 labeled wall hits,
**65 are missed** — see `eval_set/BASELINE-2026-07-23.md`, whose full missed-bounce
line reads `Missed: 71/109 … wall: 65`.

Triangulation requires the ball to be found in **both** views at the same
instant. At 35% per-view recall, the joint probability is worse than either view
alone — stereo *multiplies* the weakest link instead of fixing it. It also
doubles the user's setup burden: two phones, two mounts, two calibrations, a
pairing handshake, and a clock sync, all before a single rally.

So the effort went to the detector instead. That is the binding constraint, and
a better detector improves the single-camera product *and* is a precondition for
stereo ever being worth shipping.

**This is a deprioritization, not a repudiation.**

## The revisit gate

> **Single-view wall-hit recall clearing ~85%.**

At that point the ball is found in one view often enough that requiring it in
two stops being the binding constraint, and the geometry preserved here becomes
worth re-evaluating. Measure it the same way the baseline does:

```bash
.venv/bin/python eval_line_calls.py --eval-set eval_set/cases.jsonl
```

and read the `Missed bounces` block: the gate is `wall:` missed falling to
roughly 16 or fewer out of 109.

## How to restore

The tag is the source of truth — it holds the feature wired up and working,
which this directory deliberately does not.

**Inspect what changed since archiving:**

```bash
git diff archive/stereo-v1 -- app.py job_runner.py ios/ tests/
```

**Restore one file as it was:**

```bash
git checkout archive/stereo-v1 -- stereo_engine.py
```

**Restore the whole feature onto a branch:**

```bash
git checkout -b feat/stereo-revisit
git checkout archive/stereo-v1 -- \
  stereo_engine.py stereo_sync.py stereo_offline.py \
  tests/test_stereo_engine.py tests/test_stereo_sync.py \
  tests/test_stereo_track.py tests/test_stereo_goldens.py \
  tests/test_stereo_fuse.py tests/test_stereo_offline.py \
  tests/test_paired_session.py tests/test_stereo_endpoints.py \
  tests/generate_stereo_goldens.py tests/stereo_goldens.json \
  docs/stereo-fusion.md ios/PEER.md \
  ios/Sources/Peer ios/Sources/Stereo ios/Sources/Live ios/Tests
git rm -r archive/stereo               # the tag copies supersede these
```

Then re-apply the four unwirings that this archive removed — each is a single
commit on `chore/archive-stereo`, so `git log --oneline archive/stereo-v1..` on
that branch shows exactly what to reverse:

1. **`app.py`** — restore `import stereo_engine`, the `session_id` /
   `camera_role` / `peer_video_id` / `sync_manifest_json` form fields and their
   validation in `track_clip()`, the four matching keys in `public_job()`, and
   the `POST /api/camera-pair-check` route.
2. **`job_runner.py`** — restore the `stereo_fuse` job type, `session_runs()`,
   `maybe_start_stereo_fuse()` / `try_start_stereo_fuse()`,
   `run_stereo_fuse_job()`, the `stereo-<session_id>` run-directory convention,
   and the `try_start_stereo_fuse(...)` call at the end of the tracking job.
3. **`ios/project.yml`** — restore `NSBluetoothAlwaysUsageDescription`,
   `NSLocalNetworkUsageDescription`, and `NSBonjourServices: [_crosscourt._tcp]`,
   then run `xcodegen generate`. Never edit the generated `.xcodeproj`.
4. **`ios/Sources/`** — restore `RootTabView` pointing Play at `PlayRootView`,
   and `RecordModel`'s peer/stereo halves (`attachPeer`, `attachStereo`,
   `detachPeer`, `startStereoDemo`, the `RecordingOwner` arbitration, and the
   live-call publishers `livePresentation` / `liveTrack` / `liveImpact` /
   `flashPresentation`).

### Two things that moved rather than being archived

Both were entangled with the archive and were deliberately kept, so a restore
must not blindly overwrite them:

| Was | Is now | Why |
|---|---|---|
| `stereo_offline.py` | **`ball_track_offline.py`** (kept) + `python/stereo_offline_fuse.py` (here) | Despite the name, most of that file was the single-camera runner that exercises the local YOLOX detector. The detector half stayed and carries the history; only `fuse_clips` and the CLI were archived. The env var `STEREO_DETECTOR` was renamed **`BALL_DETECTOR`** in the split. |
| `ios/Sources/Live/SyntheticBallDetector.swift` | `ios/Sources/Tracking/SyntheticBallDetector.swift` | A general `BallDetecting` fallback used by `RecordModel` and `SyntheticDetectorTests`; it only ever lived under `Live/` by accident. |

Likewise `tests/test_stereo_endpoints.py` was a misleading name — four of its
five tests covered the single-camera `/api/camera-model` and
`/api/calibration/latest`. Those stayed as `tests/test_camera_endpoints.py`; only
`test_camera_pair_check_endpoint` is here.

### Why the archived files will not run as they sit

Deliberate — an archive that half-runs is worse than one that plainly does not:

- `tests/*.py` here still carry the `sys.path` inserts they had two directories
  up, and `pytest.ini`'s `--ignore=archive` keeps them uncollected regardless.
- `python/stereo_offline_fuse.py` imports `detections_to_track_samples` and
  `selected_detector` from `ball_track_offline`, which at the tag were in the
  same file it was split out of.
- The Swift sources are not in `ios/project.yml`'s `sources` list, so they are
  not compiled and `xcodegen generate` ignores them.
